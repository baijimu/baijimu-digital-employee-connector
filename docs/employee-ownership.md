# 本地员工与远端调用的职责边界

用户已确认：连接器拥有本机员工登记、运行配置和可调用工作区名单；平台拥有设备、用户的方法权限和会话权限，两层授权必须同时通过。

首期一个连接器实例管理一个 Codex 员工。身份使用宿主已有的 device + app 身份，不重新引入已退役的 external-agent-service 注册表。运行时只支持 Codex，不恢复其他外部 Agent 的伪支持。

## 唯一状态所有者

连接器私有数据目录中的 `employee.json` 是登记与授权的唯一源事实，配置合同为 `schemaVersion: 1.0.0`。员工名称、简介、启用状态、工作目录和工作区授权只经本地 management 操作修改。平台账号工作区名单由宿主管理的 baijimu CLI 返回；新增工作区授权须在当前目录中存在。删除授权不依赖网络查询。

注册时创建未配置、未授权的记录；保存执行配置和工作区授权后才可调用。停用和撤权阻止后续调用，不强制取消已运行的 Codex 轮次。需要立即终止执行时，在宿主停止本地应用。升级保留私有数据；卸载不得静默清除。配置持续保存到用户主动清理私有数据，无自动过期或跨请求副本。

沿用现有 runtime_operation 读写锁：每次远端调用在读锁内读取并校验登记与授权，校验后作为已受理请求释放锁；管理修改持有写锁后原子替换文件。撤权不等待运行中的 Codex RPC，成功返回后，后续请求读取新的授权。已经受理的请求不被撤权自动取消。进程重启重新读同一文件；缺失为未注册，损坏、非法版本与读取失败显式报错，不能转为默认员工。写入失败不返回成功；临时文件不能成为配置源事实。

无需平台新增数据库或登记缓存。替代方案“仅用设备方法授权”无法表达本机员工登记和本地工作区撤权，因此采用已获确认的连接器私有配置。

## 执行与权限

宿主 token 和可信工作区 Header 继续由 Device → Relay → Bridge 传输；载荷中的工作区不能扩大授权。员工尚未注册、停用、未授权工作区或未配置时，不启动 Codex、不准备目录、不发送 RPC。

远端 `employeeProfile` 只投影名称、简介、运行时和工作目录，不返回授权名单、账号或令牌。原始 `request` 方法及其权限从清单和实现中删除。远端只能确认本地配置的已有目录；目录创建与平台项目检出不再作为远端方法开放。本地项目检出 management 操作保留。

远端参数采用闭合方法合同，不能注入本机 config、审批策略、sandbox 或任意 RPC。调用中的 cwd 只能与本地工作目录一致；远端不得新建目录或检出项目。模型、系统提示和其他 AgentConfig 字段不进入本地登记文件，也不由本地 UI 保存。

AgentConfig 的唯一 Owner 继续是平台；现有执行适配器查询并校验已安装 Agent 的配置，将授权模型与系统提示传给 Codex。连接器保留该投影，不覆盖成另一个本地模型或指令。平台会话与设备权限继续按现有 Owner 校验。用户已明确纠正这一边界，lowcode-websocket 的配置传递不需要变更。

## 发布与回滚

连接器 3.0.0 和管理前端 26.1.0 已获准确版本确认。连接器 2.x 未登记员工不能自动迁移成已授权员工，升级后须在本地完成登记、配置和授权。

Runtime 的连接器依赖范围必须由目录所有者发布不可变版本，不在消费者中硬编码放宽。当前合同仅接受连接器 2.x，需要在精确 Runtime 版本与依赖关系获确认后，发布支持本地登记与授权的合同。

回滚连接器代码到 2.x 会恢复旧的远端执行能力，因此不能以回滚规避本地授权边界；事故恢复应停止本应用并保留私有配置，再选择获批准的修复版本。数据保留不代表旧版本能够读取新授权合同。
